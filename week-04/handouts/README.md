# Week 4 Handouts — Technical Architecture & Constraints

Participant-facing handouts for Week 4. Each is a standalone card, pack, or template — distribute (print or share) before the day and activity that uses it. Templates and cards are meant to be filled in; the triage-pack answer keys stay in the facilitator lab files, not here.

| Handout | Day · Activity | What it is |
|---|---|---|
| `tcd-template` | Day 1 | The 6-section Technical Concept Document skeleton with `[Day X]` tags, section-relationship notes + Friday rubric |
| `architecture-vocabulary-card` | Day 1 | 7-term monolith/microservice vocabulary + the three-question frame |
| `mono-micro-triage-pack` | Day 1 · A1 | 8 anonymized scenario cards to stance-stamp — no answers |
| `stance-stamp-sheet` | Day 1 · A1 | The 4 stances + fillable grid for the 8 cards |
| `integration-table-template` | Day 1 · A3 | 5-column integration table (system / owner / sync-async / R-W / failure) |
| `stride-letter-card` | Day 2 · A1 | The six STRIDE letters + the data-flow lens |
| `threat-documentation-template` | Day 2 · A2 | Per-threat template + top-5 roll-up |
| `compliance-frame-cards` | Day 2 · A3 | Three frame cards (SOC 2 / Privacy / Industry) with fillable checks |
| `security-brief-template` | Day 2 · A4 | One-page security brief + questions/pushbacks prep |
| `c4-legend-card` | Day 3 · A1–A2 | C4 legend + Context/Container diagram rules |
| `three-lens-prompt-card` | Day 3 · A3 | Failure / trust-boundary / evolvability review lenses |
| `slo-triage-pack` | Day 4 · A1 | 8 SLO statements to triage + failure-mode table — no answers |
| `latency-budget-reference-card` | Day 4 · A3 | Per-hop latency ranges, the walk, and a worked example |
| `tradeoff-template` | Day 5 · A2 | Trade-off template + 5 categories + FieldPulse worked examples |

**Design principle:** these are working surfaces, not narration. The mono/micro and SLO triage packs are deliberately spoiler-free — the judging is the work.
